# partly-constructive-promotion-checklist

The `partly-constructive` status (CLAUDE.md §Methodology invariants "Theme/operator status `partly-constructive` is first-class", codified cycle-012) is a **transient gate**: a theme/operator firm in its structural decomposition but carrying a named, citation-backed caveat on a constructive sub-part, with an explicit promotion condition. The gate is supposed to CLOSE (the sub-part gets firmed) — it is not a permanent escape hatch.

Promoting from `partly-constructive` to `firm` is not a mechanical status flip. The cycle-013 first-live promotion (eigsolve Sub-pattern B `LinearSolveFailed`) showed the promotion rests on interpretive choices a producer can silently make: WHICH promotion route, whether the EVIDENCE actually changed, and whether the honest-content note survives. This skill makes those choices explicit and recorded, so the critic/integrator can ratify the recorded route rather than inherit it silently.

The batch-3 lifecycle validated the mechanism by use: cycle-013 EXIT (eigsolve promoted) + ENTRY (divfree adjudicated in); cycle-014 UNBLOCK (divfree sign positively anchored) + STAYS (convergence-reason-mapping correctly stayed partly-constructive — no positive site exists); cycle-015 ENACT (divfree→firm, chebyshev-L4→firm). The "audit cycle-N / enact cycle-N+1" two-dispatch protocol closed 3× cleanly. This checklist crystallizes what those clean promotions did.

## When to invoke

- An abstractor or lifter dispatch is tasked with flipping a `## Status: partly-constructive` entry to `firm` (the ENACT pass of a gated promotion).
- A critic or integrator-per-report is ratifying such a flip (run the checklist as a mirror-check against the producer's recorded answers).

## The 4-point checklist (RECORD the answers in the promotion-record prose)

1. **Which promotion route?** Name it against BOTH:
   - the CLAUDE.md invariant's three enumerated routes — (i) an upstream positive source site, (ii) a per-line lowering-verifier audit, (iii) a literature-anchor upgrade;
   - the theme's own `## Status` gate text (the promotion condition the entry itself stated when it entered `partly-constructive`).
   If the invariant's routes and the theme's own gate are NOT the same condition (cycle-013 found the theme's gate said "shape acceptable as a methodology-level pattern" — a methodology-acceptance upgrade — whereas the invariant route is "per-line audit" — an evidence upgrade), **say so explicitly and justify which governs.** Do not fold this choice silently into a citation-refinement bundle.

2. **Did the constructive sub-part's EVIDENCE change, or only the methodology acceptance?** If the evidence is unchanged (the sub-part is STILL negative-anchor-only after the pass — e.g. Palace's `void`-returning function is unchanged, the forward-looking note is retained), state explicitly that **"firm" is being read as "no open promotion condition," NOT "the constructive sub-part is now positively anchored."** This is the load-bearing interpretation and must be surfaced, not assumed. (Contrast: cycle-014 divfree, where the lowering-verifier DID positively anchor the WeakDiv sign in Palace-owned source — a genuine evidence upgrade, route (i), so cycle-015's divfree→firm was a positive-site close, not a methodology-acceptance close.)

3. **Two-dispatch protocol satisfied?** Confirm the UNBLOCK audit ran in a PRIOR pass (a lowering-verifier confirmed the structural decomposition and identified the exact firming edits) and that THIS ENACT pass **APPLIES** those edits — never DEFERS them. The audit unblocks but does not enact; the enact pass applies then drops the caveat. (Batch-3: every promotion was audit-cycle-N / enact-cycle-N+1.)

4. **Does the permanent honest-content note survive the status flip?** When the close is a methodology-acceptance close (point 2 = evidence unchanged), the forward-looking-reconstruction note + the negative anchors STAY in the prose — only the transient `## Status` gate drops. Do not delete the honest caveat content along with the status word; the reader of a now-`firm` entry must still see that one sub-part was reconstructed and why.

## Ratification (critic / integrator)

The critic (and integrator-per-report at apply time) RATIFY the recorded route rather than inheriting it silently. Check that all 4 points are answered in the promotion-record prose; if point 1's route-choice or point 2's evidence-vs-acceptance distinction is missing or hand-waved, flag it (`rotation-quality` / `surface-or-evidence`) — a `partly-constructive`→`firm` flip without a recorded route is not ratifiable.

## Anti-pattern (the failure this prevents)

Flipping `## Status` to `firm` inside a citation-refinement bundle without naming the route or surfacing the evidence-vs-acceptance distinction — so a methodology-acceptance close masquerades as a positive-evidence close, and the invariant's clause "do NOT mark such an entry firm (the constructive sub-part isn't [positively anchored])" gets dissolved by reading "firm" as "no open promotion condition" without saying so. Cycle-013's first promotion came close to this; the recorded-route discipline is what keeps it honest.
